# Design System

## Build from decisions, not components
Create:
1. foundations
2. tokens
3. primitives
4. components
5. patterns
6. page compositions

## Tokens
At minimum:
- color
- typography
- spacing
- radius
- border
- shadow
- motion
- z-index
- breakpoints

## Component rules
Each component needs:
- purpose
- anatomy
- variants
- states
- responsive behavior
- accessibility behavior
- content constraints

## Avoid
- component proliferation
- one-off values
- inconsistent naming
- hidden magic behavior
- components that combine unrelated business logic with visual concerns
