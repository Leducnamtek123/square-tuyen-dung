# Bearplus-Level Design Skills System

A reusable AI-agent skill system for producing high-quality digital product experiences inspired by the *principles* behind premium creative studios.

This is not a visual clone of Bear Plus. It trains an agent to think through:
- product strategy
- UX
- art direction
- visual systems
- typography
- composition
- interaction
- motion
- responsive behavior
- accessibility
- implementation quality
- visual critique
- iterative improvement

## Core loop

DISCOVER → DEFINE → ART DIRECT → DESIGN → PROTOTYPE → IMPLEMENT → CRITIQUE → ITERATE

## Skills

1. `design-director` — owns the overall creative direction and quality bar.
2. `product-ux` — information architecture, flows, hierarchy, states.
3. `art-direction` — personality, mood, references, visual language.
4. `visual-design` — typography, grid, spacing, composition, color.
5. `interaction-design` — behavior, feedback, affordances, transitions.
6. `motion-design` — timing, easing, choreography, scroll, micro-motion.
7. `responsive-design` — desktop/tablet/mobile adaptation.
8. `accessibility` — inclusive interaction and semantic quality.
9. `design-system` — tokens, components, variants, consistency.
10. `creative-coding` — advanced web visuals, 3D, WebGL, shaders when justified.
11. `implementation` — translate approved design into production code.
12. `visual-qa` — screenshot-based inspection and visual regression thinking.
13. `design-critique` — structured review and prioritised fixes.
14. `reverse-engineering` — learn from excellent references without copying.
15. `design-training` — recurring exercises that improve the human/agent design eye.

## Non-negotiable principles

- Never start with components before understanding the product.
- Never use visual effects merely because they are fashionable.
- Every major visual decision needs a reason.
- Motion must communicate, guide, or reinforce hierarchy.
- Avoid generic SaaS/template aesthetics unless the product explicitly requires them.
- Prefer fewer, stronger visual decisions over decoration.
- Preserve usability while pursuing distinctiveness.
- Design the empty, loading, error, success, disabled and edge states.
- Do not invent product facts, content, business rules, or data.
- Separate design decisions from implementation constraints.
- Critique before declaring a screen finished.

## Quality gate

A design is not "done" until:
1. Product goal is clear.
2. Information hierarchy is obvious.
3. Visual personality is intentional.
4. Layout and typography feel controlled.
5. Interaction states are complete.
6. Responsive behavior is defined.
7. Accessibility is addressed.
8. Implementation does not introduce generic patterns accidentally.
9. Visual QA has been performed.
10. The top remaining issues are known.
